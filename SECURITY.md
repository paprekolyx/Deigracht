# Политика безопасности Deigracht (черновой проект)

**Версия документа:** 0.0.3-draft · 07.10.2026
**Статус проекта:** подготовка (v0.0.3) — сайта и сервера ещё нет.
Ниже — модель безопасности запланированного черновика: что будет защищено,
что отсутствует сознательно и почему. Проект следует культуре «честных
границ»: SECURITY.md обязан соответствовать фактическому состоянию,
а не намерениям (регламент §9.2) — документ обновляется каждой волной,
сдвигающей границы.

**Рамки проекта (решение владельца ВЛ-04, 07.10.2026):** Deigracht —
сугубо индивидуальный статический инструмент: без сервера, аккаунтов,
публикации документов и шаринга по ссылке. Персональные данные не
собираются (ЮР-02, 07.10.2026).

---

## 1. Какие данные где хранятся (модель черновика v0.1+)

| Данные | Где | Доступ |
|---|---|---|
| Документы пользователя (Markdown-исходник, metadata) | только браузер пользователя: localStorage/IndexedDB | другие люди и серверы доступа не имеют; сервера нет |
| Картинки в документах | **в черновых волнах v0.1.0–v0.10.0 не рендерятся** (решение владельца 07.10.2026 — изображения с v1.0.0, fp №18): вместо них плейсхолдеры, обращений к внешним хостам нет | с v1.0.0 — внешние URL, вставленные пользователем (imgur и т.п.): редактор не проксирует и не хранит их, браузер пользователя обращается к внешнему хосту напрямую — см. §3 п.3 |
| Настройки редактора (тема UI, формат печати A4/Letter, ширина панели) | localStorage браузера | локально |
| Персональные данные | нигде | сайт не имеет форм ввода ПДн, аккаунтов, аналитики и cookies-трекеров; если пользователь сам внесёт ПДн в свой документ — это содержимое его документа и зона его ответственности (ЮР-02, памятка в справке — ЮР-03) |
| Секреты (ключи API и т.п.) | нигде | серверных интеграций нет и не планируется (ВЛ-04); правило: секреты не попадают в git никогда (`.gitignore` с первого коммита, проверка в check-repo с v0.1.0) |

**Правило черновика: никаких реальных персональных данных.** Аккаунтов и форм
сбора данных нет; тестовые документы создаются с вымышленными данными.

## 2. Что защищено уже на этапе кода (планируется с v0.1.0)

| Механизм | Реализация |
|---|---|
| XSS при рендере Markdown | собственный парсер строит DOM программно (без `innerHTML` из пользовательского текста); HTML-теги в исходнике экранируются; сырой HTML не исполняется |
| Небезопасные ссылки | whitelist схем (`http:`, `https:`) для картинок и ссылок; `javascript:`/`data:` отклоняются; утилита `safeUrl()` — очистка строки от управляющих символов и пробелов до проверки схемы (установленная практика) |
| CSP | мета-тег/заголовок `default-src 'self'`; в черновых волнах `img-src 'self'` — строгий (изображений нет); ослабление для внешних картинок документов — одновременно с fp №18 (v1.0.0, АН-04) |
| Целостность репозитория | `tests/check-repo.py` (с v0.1.0): REQUIRED-файлы, локальность ресурсов (нет hotlink-скриптов/стилей), версии в шапках документов, отсутствие секретов-паттернов |
| Зависимости | ноль внешних CDN и ноль npm-зависимостей в рантайме — нечему поставлять вредоносный код; шрифты и текстуры вендорятся с фиксацией лицензий |

## 3. Чего сознательно нет в черновике (и почему)

1. **Авторизации и аккаунтов — не будет** (ВЛ-04, 07.10.2026): проект
   сугубо индивидуальный, документы хранятся у пользователя в браузере;
   серверная часть не планируется. Если рамки когда-либо будут пересмотрены
   (сейчас — не планируются), обязательный минимум известен и задокументируется
   новой ревизией SECURITY до реализации: хеширование паролей bcrypt/argon2id,
   серверные сессии (HttpOnly/Secure/SameSite), CSRF-токены, rate-limit
   и блокировки, 2FA, журнал аудита.
2. **Серверного хранения и бэкапов** — сервера нет; потеря данных при
   очистке хранилища браузера — осознанное ограничение (будет честно
   написано в UI: «экспортируйте .md регулярно»); библиотека документов —
   fp №6, экспорт `.md` и самодостаточного `.html` — fp №7б (основной способ
   переноса и передачи документов — решение ВЛ-04).
3. **Изображений в черновике вообще** (решение владельца 07.10.2026 —
   изображения отложены до v1.0.0, fp №18): черновые волны работают только
   с текстом и таблицами, `![alt](url)` — плейсхолдер, внешних обращений
   за картинками нет. С v1.0.0 редактор будет грузить их напрямую с хостов
   пользователя (без проксирования): возможны утечка IP-адреса зрителя
   внешнему хосту и битые ссылки — митигация: предупреждение в справке,
   safeUrl-whitelist, плейсхолдер битой ссылки; клиентское встраивание
   (base64, без сервера) — fp №12; серверное хранилище — только при решении
   ВЛ-12.
4. **Rate-limit и анти-спам** — нет публичных форм записи (нет сервера).
5. **Юридических страниц (политика ПДн, оферта) — не требуется** (ЮР-02,
   07.10.2026): сайт не собирает ПДн и ничего не продаёт (ЮР-01). Памятка
   пользователю (Fan Content Policy, SRD 5.1 CC-BY-4.0, ответственность
   за содержимое документов) — в справке редактора (ЮР-03, fp №10).

## 4. Хостинг и публикация

- GitHub Pages (статика, HTTPS из коробки, репозиторий публичный — решение
  владельца 07.10.2026). Риск недоступности GitHub из РФ фиксировался
  (июнь–июль 2026) — мера: zip-зеркало релиза и план переезда на российский
  статик-хостинг без изменения кода (`docs/plan/otchet.md` §5, R5); локальный
  запуск двойным кликом (сайт статический).
- Ветка `main` — единственный источник публикации; force-push не используется
  (регламент §4).

## 5. Реагирование на инциденты

Серверной обработки данных нет, поэтому инцидентный контур сводится к:
(1) уязвимость в коде репозитория (например, обход экранирования парсера) —
исправление отдельной волной/патчем, запись в регистр грабель
(`docs/reglament.md` §10) и в update-инструкцию; (2) компрометация аккаунта
GitHub — смена пароля, ревизия токенов, проверка истории коммитов на предмет
подброшенного кода. Процедуры уведомления пользователей и Роскомнадзора
не применимы: сервера и сбора ПДн нет (ЮР-02). Контакт для сообщений
о проблемах безопасности: **Albert23NO@ya.ru**.

## 6. Чек-лист безопасности перед v1.0.0 (планируется)

- [ ] фаззинг парсера на XSS-векторах (`<img onerror>`, `javascript:`,
      управляющие символы, вложенные `{{`-блоки, обрезанные блоки);
- [ ] проверка CSP фактическим заголовкам хостинга;
- [ ] отсутствие секретов в истории git (скан всего дерева);
- [ ] print/PDF не вытягивает данные за пределы документа (нет скрытых
      элементов, «печатается только разворот»);
- [ ] localStorage/IndexedDB-хранилище: квоты, деградация при переполнении,
      миграция формата документа без потерь;
- [ ] лицензионная чистота ассетов (шрифты OFL, текстуры CC0/собственные,
      никакого контента WotC — ВЛ-11);
- [ ] самодостаточный .html-экспорт (fp №7б) не содержит ничего, кроме
      документа пользователя и ресурсов редактора.
