# Политика безопасности Grimoire (черновой проект)

**Версия документа:** 0.0.1-draft · 07.10.2026
**Статус проекта:** подготовка (v0.0.1) — сайта и сервера ещё нет.
Ниже — модель безопасности запланированного черновика: что будет защищено,
что отсутствует сознательно и почему. Культура «честных границ» унаследована
из проекта Sisku: SECURITY.md обязан соответствовать фактическому состоянию,
а не намерениям (урок Sisku v0.14.0) — документ обновляется каждой волной,
сдвигающей границы.

---

## 1. Какие данные где хранятся (модель черновика v0.1+)

| Данные | Где | Доступ |
|---|---|---|
| Документы пользователя (Markdown-исходник, metadata) | только браузер пользователя: localStorage/IndexedDB | другие люди и серверы доступа не имеют; сервера нет |
| Картинки в документах | внешние URL, которые пользователь вставил сам (imgur и т.п.) | редактор не проксирует и не хранит их; при открытии предпросмотра браузер пользователя обращается к внешнему хосту напрямую — см. §3 п.3 |
| Настройки редактора (тема UI, ширина панели) | localStorage браузера | локально |
| Персональные данные | нигде | черновик не имеет форм ввода ПДн, аккаунтов, аналитики и cookies-трекеров |
| Секреты (ключи API и т.п.) | нигде | в черновике нет серверных интеграций; правило: секреты не попадают в git никогда (`.gitignore` с первого коммита, проверка в check-repo с v0.1.0) |

**Правило черновика: никаких реальных персональных данных.** Аккаунтов и форм
сбора данных нет; если в документе пользователя есть чьи-либо ПДн — это зона
ответственности пользователя (будет отражено в справке редактора).

## 2. Что защищено уже на этапе кода (планируется с v0.1.0)

| Механизм | Реализация |
|---|---|
| XSS при рендере Markdown | собственный парсер строит DOM программно (без `innerHTML` из пользовательского текста); HTML-теги в исходнике экранируются; сырой HTML не исполняется |
| Небезопасные ссылки | whitelist схем (`http:`, `https:`) для картинок и ссылок; `javascript:`/`data:` отклоняются; утилита `safeUrl()` — паттерн Sisku v0.14.0 (очистка от управляющих символов до проверки схемы) |
| CSP | мета-тег/заголовок `default-src 'self'`; `img-src` — расширение по решению (внешние картинки документов vs строгость) — АН-04 |
| Целостность репозитория | `tests/check-repo.py` (с v0.1.0): REQUIRED-файлы, локальность ресурсов (нет hotlink-скриптов/стилей), версии в шапках документов, отсутствие секретов-паттернов |
| Зависимости | ноль внешних CDN и ноль npm-зависимостей в рантайме — нечему поставлять вредоносный код; шрифты и текстуры вендорятся с фиксацией лицензий |

## 3. Чего сознательно нет в черновике (и почему)

1. **Авторизации и аккаунтов** — черновик статический, документы хранятся
   у пользователя в браузере; некого авторизовывать. Появится только вместе
   с серверным шарингом (боевой блок, отдельная ревизия SECURITY + модель
   по стандартам Sisku otchet §1.7: bcrypt/argon2id, серверные сессии
   HttpOnly/Secure/SameSite, CSRF, rate-limit, 2FA, audit_log).
2. **Серверного хранения и бэкапов** — сервера нет; потеря данных при
   очистке хранилища браузера — осознанное ограничение черновика (будет
   честно написано в UI: «экспортируйте .md регулярно»; fp №6 — библиотека
   документов, fp №7 — серверное хранение).
3. **Проксирования внешних картинок** — редактор грузит их напрямую с хостов
   пользователя: возможны утечка IP-адреса зрителя внешнему хосту и битые
   ссылки при удалении файла автором. Митигация в UI-справке; прокси/загрузка
   картинок в хранилище — боевой блок (fp №12).
4. **Rate-limit и анти-спам** — нет публичных форм записи (нет сервера).
5. **Юридических страниц (политика ПДн, оферта)** — не требуются, пока сайт
   не собирает ПДн и не продаёт услуги; появятся в боевом блоке при добавлении
   серверных функций (шаблон — ЮР-02, по образцу Sisku privacy.html).

## 4. Хостинг и публикация

- GitHub Pages (статика, HTTPS из коробки, репозиторий публичный — решение
  владельца 07.10.2026). Риск недоступности GitHub из РФ фиксировался
  (июнь–июль 2026) — мера: zip-зеркало релиза и план переезда на российский
  статик-хостинг без изменения кода (`docs/plan/otchet.md` §5).
- Ветка `main` — единственный источник публикации; force-push не используется
  (регламент §4).

## 5. Реагирование на инциденты

В черновике нет серверной обработки данных, поэтому инцидентный контур
сводится к: (1) уязвимость в коде репозитория (например, обход экранирования
парсера) — исправление отдельной волной/патчем, запись в регистр грабель
(`docs/reglament.md` §10) и в update-инструкцию; (2) компрометация аккаунта
GitHub — смена пароля, ревизия токенов, проверка истории коммитов на предмет
подброшенного кода. Контакт для сообщений о проблемах безопасности:
**Albert23NO@ya.ru**. При появлении серверной части раздел будет расширен
процедурой уведомления пользователей и (при обработке ПДн) Роскомнадзора
по ст. 21 152-ФЗ (24 ч / 72 ч).

## 6. Чек-лист безопасности перед v1.0 (планируется)

- [ ] фаззинг парсера на XSS-векторах (`<img onerror>`, `javascript:`,
      управляющие символы, вложенные `{{`-блоки, обрезанные блоки);
- [ ] проверка CSP фактическим заголовкам хостинга;
- [ ] отсутствие секретов в истории git (скан всего дерева);
- [ ] print/PDF не вытягивает данные за пределы документа (нет скрытых
      элементов, «печатается только разворот»);
- [ ] localStorage-хранилище: квоты, деградация при переполнении, миграция
      формата документа без потерь;
- [ ] лицензионная чистота ассетов (шрифты OFL, текстуры CC0/собственные,
      никакого контента WotC).
