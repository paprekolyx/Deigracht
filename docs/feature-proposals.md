ЮР-03 — памятка в fp №10)
**Ведёт:** аналитик проекта · Albert23NO@ya.ru

Правила ведения карт (регламент §5): номер карты не переиспользуется;
реализованная карта переносится в блок «Уже реализовано» сразу после волны
(до приёмки); отменённая — заменяется статусной заглушкой с сохранением
номера и кода решения (урок практики: на номера ссылаются другие документы);
новая идея — новая карта в конце нумерации.

Формат карты: **бизнес-задача → эскиз → осуществимость → оценка → волна**.

## Ядро (v0.1.0–v0.3.0)

### fp №1. Редактор с живым предпросмотром — волна v0.1.0, 2–3 РД
**Задача:** пользователь пишет Markdown слева и сразу видит книжный разворот
справа — как в Homebrewery.
**Эскиз:** две панели (перетаскиваемая граница); debounce-рендер ~300 мс;
синхронная прокрутка панелей (приблизительная, по пропорции); счётчик
страниц/слов; горячие клавиши (Ctrl+S — сохранить в браузер, Ctrl+P — PDF).
**Осуществимость:** vanilla JS, без зависимостей; сложность — средняя
(синхроскролл и производительность на 180 тыс. знаков).

### fp №2. Рендерер синтаксиса Homebrewery V3 — волны v0.1.0–v0.3.0, 6–9 РД
**Задача:** существующие документы Homebrewery (в т.ч. документ владельца)
открываются и выглядят так же.
**Состав по волнам** (матрица — otchet §1.4): v0.1.0 — Markdown-ядро
(заголовки, текст, списки, таблицы, картинки, `\page`, metadata-блок);
v0.2.0 — `{{wide}}`, `{{note}}`, `{{descriptive}}`, `{{monster}}` + `___`-
статблоки, `{{toc}}` (ручной, как в источнике), `{{column-count}}`,
`{{pageNumber}}`; v0.3.0+ — `{{imageMask*}}` (edge/corner/center — самая
сложная часть: CSS mask-image, оценка уточняется в АН-06).
**Осуществимость:** высокая для основной части; imageMask — средняя.
Homebrewery — MIT, синтаксис документирован публично; код не копируем.

### fp №3. Тема «книга правил» (5ePHB-стиль) с кириллицей — v0.1.0, 3–4 РД
**Задача:** разворот выглядит как страница официальной книги: пергамент,
две колонки, красно-коричневые заголовки с линейками, буквицы, рамки
врезок, статблоки с двойными линейками, колонтитулы и номера страниц.
**Эскиз:** токены темы (CSS-переменные: палитра, шрифты, поля, колонки);
шрифты — **готического склада, OFL с кириллицей** (ВЛ-08): кандидаты —
Cormorant Unicase/SC (заголовки), Alegreya (текст), Fira Sans Condensed
(статблоки/UI), Ruslan Display (буквицы/акцент, опционально) — ADR-002
ред. 1.1, проверка на эталоне — АН-03; текстура пергамента — CC0/собственная,
умеренная стилизация (ВЛ-11: без копирования оформления книг WotC).
**Осуществимость:** высокая; риск — типографика кириллических буквиц и
переносов (проверка эталоном).

### fp №4. Экспорт в PDF — v0.1.0, 2–3 РД
**Задача:** «Сохранить как PDF» даёт файл, идентичный экранному развороту
(65 страниц эталона — без «поехавших» колонок).
**Эскиз:** print.css (`@page`, **переключатель A4/Letter** — ВЛ-07: дефолт
Letter, эталон печатался в Letter, на A4 у Homebrewery оставались белые
полосы внизу; ADR-003 ред. 1.1), поля, скрытие UI редактора; 1 экранная
.page = 1 печатная; колонтитулы и `{{pageNumber}}` — через CSS-счётчики/
JS-подстановку; кнопка «Печать / PDF».
**Осуществимость:** высокая (принцип тот же, что в Homebrewery); риск —
расхождения печати между браузерами (тест-матрица — tehpasport §8).

### fp №5. Импорт документов и эталон приёмки — v0.2.0, 1–2 РД
**Задача:** перенести существующую библиотеку документов из Homebrewery
без ручного переразмечивания.
**Эскиз:** «Открыть .md/.txt» (file input + drag&drop) → парсинг metadata →
рендер; авто-миграция известных расхождений синтаксиса (если найдутся);
**критерий приёмки:** «Всемирная история» (65 стр., 211 `{{`-блоков,
49 `\page`, 3 монстр-блока, 577 строк таблиц, 9 картинок) рендерится и
печатается корректно; метрики сверяются с `data/etalon/` (регресс-тест
регламент §8.4). Второй эталон не требуется — блоки те же (ВЛ-10).
**Осуществимость:** высокая; эталон уже есть у владельца.

## Бэклог (порядок утверждает владелец — ВЛ-02)

### fp №6. Библиотека документов в браузере — целевая v0.3.0, 2–3 РД
**Задача:** документы не теряются между сессиями: список «моих книг»
(название из metadata, дата правки, размер), автосохранение, дублирование,
удаление, экспорт/импорт .md одним файлом. Хранение — localStorage →
IndexedDB при исчерпании квоты. **Эскиз:** drawer библиотеки в редакторе.

### fp №7. Шаринг по ссылке — ОТМЕНЁН (решение ВЛ-04, 07.10.2026)
_Статусная заглушка (номер сохранён исторически — на него ссылаются другие
документы):_ серверный шаринг не реализуется — проект сугубо индивидуальный,
без аккаунтов и публикации документов. Потребность «показать документ
другому» закрывает **fp №7б** (самодостаточный .html) и PDF-экспорт (fp №4).

### fp №7б. Экспорт самодостаточного .html документа — целевая v0.3.0, 1–2 РД
**Задача:** передать документ одним файлом без сервера: «Экспорт HTML» →
единственный .html со встроенными стилями, шрифтами (woff2 base64) и
разметкой книги; открывается двойным кликом, печатается в PDF.
**Эскиз:** кнопка в тулбаре; картинки — по URL (или base64 при включённом
fp №12); предупреждение о размере файла. **Осуществимость:** высокая
(шаблон экспорта = theme-book.css + print.css инлайном).

### fp №8. Свои темы (конструктор) — целевая v0.5.0, 4–6 РД
**Задача:** пользователь меняет палитру/шрифты/поля своей книги и сохраняет
тему. **Эскиз:** панель токенов + живой предпросмотр; паттерн «конструктор
брендбука»: проверка контрастов WCAG, шаблоны палитр, режим сравнения
«сохранённая vs новая». Задел — токены темы (fp №3).

### fp №9. Дополнительные темы оформления — целевая v0.5.0+, 2–3 РД за тему
**Задача:** альтернативные развороты: «книга мастера» (тёмная, DMG-стиль),
«современная вёрстка» (Swiss-стиль), «тёмное фэнтези». Каждая тема — набор
токенов + свои декоративные элементы (орнаменты — CC0/собственные, ВЛ-11).

### fp №10. Справка синтаксиса, панель сниппетов и юридическая памятка — целевая v0.3.0, 2–3 РД
**Задача:** новичок собирает монстр-блок/врезку кнопкой, не заучивая
синтаксис; пользователь знает правовые рамки.
**Эскиз:** боковая панель сниппетов (как в Homebrewery): вставка заготовок
`{{monster}}`, `{{note}}`, таблиц, `\page`; `help.html` — справка со всеми
блоками и живыми примерами + **памятка о Fan Content Policy WotC и SRD 5.1
(CC-BY-4.0)** и об ответственности пользователя за содержимое документов,
включая внесённые им ПДн (ЮР-03, ЮР-02 — решения 07.10.2026).

### fp №11. Автосборка оглавления — целевая v0.4.0, 2 РД
**Задача:** `{{toc}}` генерируется из заголовков с реальными номерами страниц
(в документе владельца TOC собран вручную — 82 записи). **Осуществимость:**
средняя: двухпроходный рендер (сначала пагинация, потом TOC), якоря `#pN`.

### fp №12. Встраивание картинок в документ (клиентское) — порядок по ВЛ-02 (предложение: v0.4.0+), 2–3 РД
**Задача:** картинки не зависят от внешнего хостинга (imgur): файл →
сжатие в браузере → base64/dataURL в документ. **Эскиз:** кнопка «встроить»
у картинки; предупреждение о размере (документ растёт); без сервера
(ВЛ-04 — серверное хранилище не планируется). Паттерн: черновая загрузка
фото со сжатием в браузере (практика предыдущего проекта).

### fp №13. История версий документа — целевая v0.5.0, 3–4 РД
**Задача:** «случайно удалил главу» — откат. **Эскиз:** снапшоты в
IndexedDB (последние N), просмотр различий — позже; всё на клиенте.

### fp №14. GitHub-интеграция (gist) — ОТМЕНЁН (решение ВЛ-04, 07.10.2026)
_Статусная заглушка (номер сохранён исторически):_ аккаунтов и внешних
API-интеграций не будет; хранение — только браузер пользователя.

### fp №15. Мобильная адаптация — целевая v0.4.0, 2–3 РД
**Задача:** правки и просмотр с телефона (панели — вкладки вместо
двухколоночника; печать — десктопная). Живое тестирование на реальных
устройствах — обязательная часть приёмки волны.

### fp №16. Тёмная тема UI редактора — целевая v0.4.0, 1–2 РД
UI редактора (не книги!) в тёмной палитре; `prefers-color-scheme` +
переключатель; применение до отрисовки — без «моргания».

### fp №17. Конструктор статблоков/заклинаний — целевая v0.6.0, 4–6 РД
**Задача:** форма «существо» (ХП, КД, скорости, атаки, способности) →
готовый `{{monster}}`-блок в документ. Снижает порог входа; проверяет
форматирование по SRD-образцам (фрагменты SRD 5.1 — CC-BY-4.0, атрибуция
по LICENSE ч.3 п.3).

### fp №18. Интернационализация интерфейса (i18n) — не раньше v1.x, 3–4 РД
**Задача:** интерфейс редактора и справки на других языках (RU → EN).
**Решение владельца (ВЛ-09, 07.10.2026):** только русский; иностранные
языки не раньше v1.x по отдельному запросу — карта добавлена одним из
последних пунктов бэклога. **Эскиз:** словарь строк UI + атрибут `lang`;
язык книги не зависит от языка интерфейса.
