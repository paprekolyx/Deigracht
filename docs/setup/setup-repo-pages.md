## Шаг 0. Переименование репозитория (волна v0.0.2)

Репозиторий создан 07.10.2026 под рабочим именем `Grimoire`; название
проекта утверждено владельцем — **Deigracht** (ВЛ-01). Переименование:

1. `https://github.com/paprekolyx/Grimoire` → **Settings** → **General** →
   блок «Repository name» → вписать `Deigracht` → **Rename**;
2. GitHub автоматически сохраняет перенаправление со старого URL (git remote
   и веб-ссылки продолжают работать, но лучше обновить явно);
3. если используется локальный git:
   `git remote set-url origin https://github.com/paprekolyx/Deigracht.git`;
4. будущий адрес сайта (Pages, с волны v0.1.0):
   `https://paprekolyx.github.io/Deigracht/`.

Проверка названия выполнена до переименования (АН-11 —
`docs/plan/otchet.md` §7): конфликтов не обнаружено.

## Шаг 1. Создание репозитория (исполнено 07.10.2026 — для полноты инструкции)

1. Войти в аккаунт GitHub (`paprekolyx`).
2. **New repository**:
   - Repository name: **`Deigracht`** (до 07.10.2026 был создан как
     `Grimoire` — см. шаг 0);
   - Public (решение владельца 07.10.2026);
   - **НЕ ставить** галочки «Add a README», «.gitignore», «license» —
     эти файлы приходят в пакете волны (иначе будет конфликт при первой
     загрузке);
   - Create repository.
3. Ветка по умолчанию — `main` (Settings → Branches при необходимости).

## Шаг 2. Загрузка пакета волны

Состав пакета — всегда в §2 update-инструкции текущей волны
(`docs/update/update-vXXXX.md`).

**Вариант А — веб-интерфейс (без установки git):**
1. В репозитории: «uploading an existing file» (или Add file → Upload files);
2. перетащить файлы пакета с сохранением структуры папок: веб-загрузчик
   GitHub понимает пути `docs/plan/…` при перетаскивании папок; `.keep`-файлы
   загружать так же (пустые файлы допустимы);
3. Commit message: версия волны (например, **`0.0.2-draft`**); Commit
   directly to `main`;
4. Commit changes.

**Вариант Б — git (если установлен):**
```bash
cd <папка-с-пакетом>/Deigracht
git init -b main
git add -A
git commit -m "0.0.2-draft"
git remote add origin https://github.com/paprekolyx/Deigracht.git
git push -u origin main
```
Правило: force-push не используется (регламент §4.1).

Проверка загрузки — чек-листы §4–§5 update-инструкции волны
(в т.ч. `grep -c '^# '` = 1 для каждого MD — грабля №1).

## Шаг 3. GitHub Pages — с волны v0.1.0

В документационных волнах (0.0.x) публиковать нечего (index.html появится
в волне v0.1.0). Pages включается в волне v0.1.0 по её update-инструкции:
1. Settings → Pages → Build and deployment → Source: **Deploy from a branch**;
2. Branch: `main`, папка `/ (root)`; Save;
3. Адрес сайта: `https://paprekolyx.github.io/Deigracht/`;
4. после публикации — обновлять сайт с **Ctrl + F5** (кэш Pages).

## Шаг 4. Зеркало (на случай недоступности GitHub)

Известный риск: массовые сбои доступа к GitHub из РФ (июнь–июль 2026). Меры:
- каждый пакет волны хранится локально в виде zip-архива релиза;
- сайт статический: полный аналог разворачивается на любом российском
  статик-хостинге (Beget и т.п.) копией файлов без изменений кода;
- локальный просмотр редактора работает и без хостинга — двойным кликом
  по index.html (ADR-001: file:// совместим).
