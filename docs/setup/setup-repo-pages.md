# Инструкция 1: репозиторий и GitHub Pages

**Статус:** событийный документ [С] (реестр §6.1); создан волной v0.0.1
(07.10.2026). Меняется только при изменении порядка публикации.
**Для:** владельца проекта (доступ к аккаунту GitHub — у владельца;
аналитик готовит пакеты загрузки и чек-листы).

---

## Шаг 1. Создание репозитория

1. Войти в аккаунт GitHub (тот же, что для Sisku: `paprekolyx`).
2. **New repository**:
   - Repository name: **`Grimoire`** (рабочая заглушка ВЛ-01; если владелец
     выберет другое имя — создать сразу с ним и сообщить аналитику: имя
     входит в URL Pages и в документы);
   - Public (решение владельца 07.10.2026);
   - **НЕ ставить** галочки «Add a README», «.gitignore», «license» —
     эти файлы приходят в пакете волны (иначе будет конфликт при первой
     загрузке);
   - Create repository.
3. Ветка по умолчанию — `main` (Settings → Branches при необходимости).

## Шаг 2. Загрузка пакета v0.0.1

**Вариант А — веб-интерфейс (без установки git):**
1. В пустом репозитории: «uploading an existing file»;
2. перетащить файлы пакета (состав — `docs/update/update-v001.md` §2)
   с сохранением структуры папок: веб-загрузчик GitHub понимает пути
   `docs/plan/…` при перетаскивании папок; `.keep`-файлы загружать так же
   (пустые файлы допустимы);
3. Commit message: **`0.0.1-draft`**; Commit directly to `main`;
4. Commit changes.

**Вариант Б — git (если установлен):**
```bash
cd <папка-с-пакетом>/Grimoire
git init -b main
git add -A
git commit -m "0.0.1-draft"
git remote add origin https://github.com/paprekolyx/Grimoire.git
git push -u origin main
```
Правило: force-push не используется (регламент §4.1).

Проверка загрузки — чек-лист `docs/update/update-v001.md` §4–§5
(в т.ч. `grep -c '^# '` = 1 для каждого MD — грабля №1).

## Шаг 3. GitHub Pages — НЕ в этой волне

В v0.0.1 публиковать нечего (index.html появится в волне v0.1.0).
Pages включается в волне v0.1.0 по её update-инструкции:
1. Settings → Pages → Build and deployment → Source: **Deploy from a branch**;
2. Branch: `main`, папка `/ (root)`; Save;
3. Адрес сайта: `https://paprekolyx.github.io/Grimoire/` (или выбранное имя);
4. После публикации — обновлять сайт с **Ctrl + F5** (кэш Pages).

## Шаг 4. Зеркало (на случай недоступности GitHub)

Прецедент: массовые сбои доступа к GitHub из РФ (июнь–июль 2026, урок
Sisku). Меры:
- каждый пакет волны аналитик хранит локально в виде zip-архива релиза;
- сайт статический: полный аналог разворачивается на любом российском
  статик-хостинге (Beget и т.п.) копией файлов без изменений кода;
- локальный просмотр редактора работает и без хостинга — двойным кликом
  по index.html (ADR-001: file:// совместим).
