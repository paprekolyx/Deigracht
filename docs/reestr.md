# Реестр документации Grimoire

**Ведёт:** _аналитик проекта_ · _Albert23NO@ya.ru_
**Статус:** _официальный реестр документации репозитория (редакция 1.0,
07.10.2026 — волна v0.0.1)_
**Место публикации:** _`docs/reestr.md` (постоянное имя файла; редакция —
в этой шапке; обновление — перезаписью в составе пакета волны, правило
регламента §2.3). Реестр — истина о составе документов и циклах их
обновления; расхождение реестра с папками считается багом документации._

### Условные обозначения циклов обновления
[В] — меняется в каждой волне (версионно-синхронный документ);
[Н] — создаётся заново в каждой волне (старые не редактируются);
[С] — событийный: меняется только при наступлении события;
[З] — замороженный/исторический: текст неизменяем (допускаются только
помеченные служебные вставки).

Версия проекта на момент составления: 0.0.1-draft. Код сайта отсутствует —
позиции, которые появятся с волной v0.1.0, помечены «(план)».

## 1. Корневые документы репозитория

### 1.1. README.md — [В]
Визитка репозитория: статус, возможности, стек, структура, инструкции,
changelog, юридические оговорки, контакты.
Что меняется с каждой версией:
* первые строки шапки: > **v0.X.Y-draft · ДАТА.** + краткий статус;
* таблица «Версионирование»: новая строка волны (строго в хронологии —
  регламент §1.5);
* «Структура репозитория» — при новых файлах/папках;
* «Что будет у сайта» — при сдвиге состава волн;
* «Юридические оговорки» — при изменении юрконтура.

### 1.2. LICENSE.md — [В формально, по содержанию редкий]
Лицензия проекта (части: код MIT / творческое содержимое CC BY-NC-ND 4.0 /
оговорки: заглушка имени, WotC Fan Content, SRD, шрифты, документы
пользователей, ПДн, боевая версия).
Что меняется: шапка «Версия документа: 0.X.Y-draft · ДАТА» (точка
синхронизации); содержание — только при изменении юридического контура
(подстановка правообладателя в M0, смена названия, подключение серверных
функций).

### 1.3. SECURITY.md — [В]
Политика безопасности черновика: где какие данные, что защищено, чего
сознательно нет (честные границы), инциденты, чек-лист перед v1.0.
Что меняется: шапка «Версия документа»; §1–§3 — волной, сдвигающей границы
(появление сервера, шаринга, аккаунтов); правило: SECURITY обязан
соответствовать факту, а не намерениям (регламент §9.2).

### 1.4. .gitignore — [С]
Что меняется: новая строка — при появлении нового класса непубликуемых
файлов, с комментарием «зачем» (регламент §9.1).

### 1.5. assets/js/config.js — [В] (план, с v0.1.0)
Единственная обязательная правка каждой кодовой волны:
`const SITE_VERSION = '0.X.Y-draft';` — точка синхронизации версий
(регламент §1.4). В v0.0.1 файла нет.

## 2. Документы docs/

### 2.1. docs/reglament.md — [С], своя версия (сейчас 1.0)
Основные правила ведения проекта: волны и SemVer, структура и циклы [В]/[Н]/
[С]/[З], правила документов, ветки и коммиты, трекерные коды, приёмка и
ревью, update-инструкции, тесты, безопасность, регистр грабель.
Что и когда меняется: новая ревизия при появлении нового правила (обычно —
из §7 «Урок для регламента» update-инструкции волны); строка истории ревизий
в конце документа обязательна.

### 2.2. docs/reestr.md — [В] (этот файл)
Реестр документации: состав, назначение, циклы, «что и когда меняется».
Постоянное имя, редакция — в шапке; обновляется перезаписью в пакете волны.

### 2.3. docs/tehpasport.md — [В]
Технический паспорт: архитектура, стек и обоснование, структура репозитория,
парсер и рендер, данные, шрифты и темы, тестирование, ограничения, план.
В v0.0.1 — каркас волны 0 (честно помечен).
Что меняется с каждой версией: шапка «Версия проекта / Дата паспорта»;
состав репозитория; счётчики (страницы, модули, шрифты); §11 — новый пункт
при каждом эксплуатационном уроке; §12 — при сдвиге границ; §15 — версии
компонентов.

### 2.4. docs/feature-proposals.md — [С]
Бэклог функционала: нумерованные fp-карты (бизнес-задача + эскиз +
осуществимость + оценка + целевая волна); блок «Уже реализовано».
Что и когда меняется: реализованная карта переносится в «Уже реализовано»
сразу после волны (до приёмки); новая идея — новая карта; приоритизация
с владельцем — перестановка порядка разработки; номер карты не
переиспользуется (урок Sisku fp №3).

## 7. Инструменты контроля

### 7.1. tests/check-repo.py — [С], своя версия (план; с v0.1.0)
Автопроверка целостности репозитория (без сети; `python3 tests/check-repo.py`;
exit 0 = зелёный, индикатор качества волны). Минимальный состав v1.0
задачи АН-01: REQUIRED-файлы; версии README/SECURITY/LICENSE = SITE_VERSION;
хронология таблицы версий; локальность `src/href`; отсутствие секретов-
паттернов; `grep -c '^# '` = 1 для всех MD. Шапка-комментарий — строка
changelog «vX.Y (версия проекта): что добавлено».

### 7.2. data/ — бэкапы и эталоны (план)
С кодовых волн: `data/etalon/` — эталонный документ «Всемирная история»
(.md + ожидаемые метрики рендера: число страниц/блоков — для регресс-теста
§8.4 регламента). Чувствительных данных нет; состав и формат фиксируются
ревизией этого реестра при создании.
