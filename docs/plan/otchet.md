## 1. Homebrewery: что это и что нам нужно повторить

### 1.1. Общие сведения

The Homebrewery (naturalcrit) — веб-инструмент «Create authentic looking
D&D content using Markdown»: редактор + живой предпросмотр книжного
разворота, темы (5ePHB, 5eDMG, SwissModern и др.), сохранение brew'ов
(анонимные — в базу, авторизованные — через GitHub), шаринг по ссылке,
экспорт в PDF печатью браузера. Распространяется под **MIT License**
(github.com/naturalcrit/homebrewery) — изучать можно свободно; **код мы не
копируем**: стек оригинала (React, Node.js, MongoDB) несовместим с нашим
ADR-001 «статика без сборки», а самостоятельная реализация на vanilla JS
проще в поддержке владельцем. Синтаксис V3 публично документирован —
используем как спецификацию совместимости.

### 1.2. Почему проект вообще нужен (проблема владельца)

Оригинальный сайт у владельца **перестал работать** (недоступность
naturalcrit.com — единичные сбои/блокировки не контролируются пользователем
из РФ). Документы-то остались (исходник «Всемирная история» — .md), но
средства красиво собрать из них книгу и PDF — нет. Задача: инструмент,
который (а) понимает существующие .md, (б) не зависит от зарубежного
сервиса, (в) хорошо работает с кириллицей.

### 1.3. Разбор эталонного документа владельца (данные для матрицы поддержки)

«Всемирная история» (Путеводитель по Дейгрихту): ~180 тыс. знаков,
PDF-экспорт — **65 страниц**. Инвентаризация синтаксиса:

**Ключевой finding — кириллица.** Шрифты PDF-экспорта эталона:
`TimesNewRomanPSMT/BoldMT/ItalicMT/BoldItalicMT` + кастомные `MyFont`,
`ScalySansRemake` (латинские книжные шрифты Homebrewery). Это значит:
**весь русский текст документа отпечатан Times New Roman** — книжные шрифты
оригинала (Bookinsanity и др.) не содержат кириллицы, браузер подставляет
fallback. Отсюда требование fp №3: шрифты темы — только с полной кириллицей
(OFL), и регресс-эталон проверяет именно русский текст.

### 1.4. Матрица совместимости V3 (целевая)

| Группа | Состав | Целевая совместимость |
|---|---|---|

| Блоки | wide, note, descriptive, monster, column-count, pageNumber, toc | полная по внешнему виду (v0.2.0) |

Расхождения фиксируем честно: неизвестный `{{модификатор}}` рендерится
как обычный блок с видимой плашкой «не поддержано» (а не молча ломается).

## 2. Архитектура (схема — техпаспорт §2)

Конвейер: **исходник → parser.js (MD-AST) → blocks.js (V3-структуры) →
render.js (программный DOM) → pages.js (пагинация) → theme-book.css
(вид) → print.css (PDF)**. Обратный ход: storage.js (IndexedDB) ↔ редактор.
Сервера нет: всё считается в браузере, данные не покидают устройство
(кроме внешних картинок, которые тянет сам браузер — SECURITY §3.3).

## 3. Структура репозитория

Целевая — техпаспорт §4. Текущая (v0.0.1) — README «Структура». Принцип:
документы рядом с кодом (docs/), тесты в tests/, эталоны в data/etalon/,
ассеты в assets/ — как в Sisku.

## 4. ADR (архитектурные решения)

### ADR-001. Статика без сборки (принято 07.10.2026, владелец)
**Решение:** HTML5/CSS3/vanilla JS ES6+, модули `<script defer>`, без
фреймворков, бандлеров, npm-рантайма и внешних CDN; хостинг — GitHub Pages.
**Альтернативы:** Vite+React/TS (как оригинальный Homebrewery) — мощнее,
но: toolchain, зависимости, сборка, сложнее для поддержки владельцем;
**отклонено** решением владельца 07.10.2026 (вопрос стека).
**Последствия:** свой парсер (риск R2 — митигируется эталоном и матрицей
§1.4); производительность на больших документах — debounce + инкрементальный
перерендер по страницам (§9 техпаспорта); всё вендорим.

### ADR-002. Шрифты темы (ревизия 1.1 — 07.10.2026, по ВЛ-08)
**Решение владельца (ВЛ-08, 07.10.2026):** «Нужен стиль готики, похожий на
шрифты из официальных книг ДНД, но доступный без покупки лицензии. Попробуем
вариант, который предложишь ты, при необходимости изменим в одну из волн
разработки».
**Уточнение аналитика:** официальные книги D&D (PHB/DMG 2014) используют не
фрактуру: текст — старопечатная антиква (Bookinsanity, дженсоноподобная),
заголовки — «траяноподобные» капители (Mr Eaves), статблоки — гуманистический
гротеск (Scaly Sans). Настоящая чёрная готика (blackletter) с кириллицей
в свободных лицензиях практически отсутствует. Предложенный набор воспроизводит
«старокнижный» характер официальных изданий и полностью свободен:
- заголовки (H1/H2, капители): **Cormorant Unicase** / Cormorant SC
  (OFL, кириллица);
- текст книги: **Alegreya** (OFL, кириллица) — динамичная старопечатная
  антиква литературного склада; альтернативы: Literata, PT Serif;
- статблоки и UI: **Fira Sans Condensed** (OFL, кириллица);
- буквицы/готический акцент (опционально): **Ruslan Display** (OFL,
  кириллица, старославянский колорит);
- моноширинный (служебный): JetBrains Mono (OFL, кириллица).
**Исполнение:** woff2-подмножества (кириллица+латиница), OFL-тексты и
атрибуция — в assets/fonts/, перечень — техпаспорт §13. Прогон на эталоне
(буквицы, заголовки, переносы, таблицы) — АН-03, до v0.1.0; замена набора
возможна до v0.2.0 без переделок (токены темы). Требование без изменений:
только OFL с полной кириллицей (грабля №7 — кириллица не должна проваливаться
в fallback).

### ADR-003. Геометрия страницы (ревизия 1.1 — 07.10.2026, по ВЛ-07)
**Решение владельца (ВЛ-07, 07.10.2026):** «Делаем переключатель A4/Letter.
PDF эталон печатался в Letter, так как в А4 оставались белые подвалы внизу
страницы» (геометрия страниц Homebrewery — Letter; при печати на A4 остаётся
белая полоса снизу).
**Решение:** переключатель формата **A4/Letter** в настройках печати,
дефолт — **Letter** (геометрия эталона); высота экранного контейнера .page
строго соответствует выбранному формату (`@page` size/margins — по формату);
цель — чистая печать обоих форматов без белых полос (проверка — АН-05);
выбор формата сохраняется в localStorage.

### ADR-004. Хранение документов в черновике
localStorage (быстрый старт, ~5 МБ) → IndexedDB (библиотека, fp №6, v0.3.0).
Формат записи: metadata + исходный .md как есть (совместимость с Homebrewery),
рендер — всегда из исходника (никакого «только DOM»).

## 6. Вывод

Проект **Deigracht** стартует на проверенной дисциплине Sisku (волны, реестр, update-
инструкции, check-repo, честные границы) и с ясной технической рамкой:
статический редактор без зависимостей, собственная реализация V3-синтаксиса,
кириллица первого класса, PDF печатью. Первый код — волна v0.1.0 после
закрытия АН-03/АН-05/АН-07 (шрифты, геометрия, прототип пагинации).
Эталон приёмки уже существует — документ владельца «Всемирная история».

## 7. Приложение: проверка названия Deigracht (АН-11, 07.10.2026)

Поручение владельца (ВЛ-01): «на всякий случай проверяем совпадения, чтобы
не было юридических ограничений использования». Выполнено 07.10.2026
(веб-поиск, GitHub Search API):

| Источник | Запрос | Результат |
|---|---|---|
| Веб-поиск | «Deigracht» | единственное совпадение — артефакт OCR в оцифрованной голландской газете Algemeen Handelsblad от 28.11.1909 («tot demping deigracht» — о засыпке канала; не бренд, не организация) |
| Веб-поиск | «Deigracht» + trademark/brand/game/компания | релевантных результатов нет |
| GitHub Search API | repositories / users / issues: `deigracht` | total_count = 0 во всех категориях |
| Известные франшизы (игры, ПО, товары) | — | совпадений не выявлено |

**Вывод:** название фактически уникально; юридических препятствий для
использования в бесплатном некоммерческом проекте (ЮР-01) не обнаружено.
**Ограничения проверки:** реестры товарных знаков (ФИПС/Роспатент, EUIPO,
USPTO, WIPO Global Brand DB) не запрашивались — для бесплатного инструмента
без продаж это избыточно на текущем этапе; повторная проверка рекомендуется
перед покупкой домена, регистрацией юрлица или любой монетизацией (риск R8).
Слово морфологически голландское («gracht» — канал), читается как
«Дейграхт»/«Де-Играхт» — произношение фиксируем за владельцем.
