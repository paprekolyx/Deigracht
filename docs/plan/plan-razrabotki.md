## 4. Риски

Полный реестр — `docs/plan/otchet.md` §5 (R1–R8); влияющие на план:
R1 шрифты/кириллица (кандидаты предложены), R3 точность пагинации (допуск
±1 стр., эталон-регресс), R5 доступность GitHub (зеркало), R6 сложность
imageMask (перенесён в v1.0.0 — вместе с изображениями; исследование АН-06),
R7 внешние картинки (в черновике не рендерятся — решение владельца; полная
митигация — v1.0.0), R8 название (проверено — otchet §7).
**Новый риск R9 (ред. 1.2):** длинная очередь волн v0.3.0–v0.10.0 при
однопользовательской разработке — вероятность пересмотра приоритетов
владельцем; мера: порядок меняется только новым решением ВЛ (регламент §5,
план §5), состав ближайших 2–3 волн считается замороженным.

## 5. Правила пересмотра плана

- статус волны (дата завершения, фактический состав) — вносится в таблицу
  по факту, новой строкой истории ревизий;
- состав утверждённой волны меняется только решением владельца или находкой
  ревью — с фиксацией (код ВЛ/Ф) в строке волны;
- новые идеи — только через fp-карты (регламент §5), не прямым редактированием
  плана;
- приоритеты fp — истина в `docs/feature-proposals.md` (ред. 2.0,
  утверждены владельцем 07.10.2026).

## 7. Документационный оборот волны (памятка)

3. подготовка пакета: update-vXXXX.md, правки [В]-документов, версии в шапках;

5. проверка (update §5, check-repo);
6. уведомление владельца → записки приёмки → priemka-v0XX.md → задачи
   следующей волны.
