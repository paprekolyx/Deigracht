## 2. Критерии завершения волны v0.0.1 (текущей)

1. Репозиторий создан: `https://github.com/paprekolyx/Grimoire` (public,
   ветка main) — по `docs/setup/setup-repo-pages.md`;
2. пакет файлов загружен (состав — `docs/update/update-v001.md` §2);
3. коммит(ы) с сообщением `0.0.1-draft`;
4. чек-лист `update-v001.md` §5 пройден (версии в шапках, реестр = факт,
   нет дублей заголовков);
5. владельцу отправлено уведомление со ссылкой на опросник
   (`docs/plan/voprosy-vladeltsu.md`).

## 4. Риски

Полный реестр — `docs/plan/otchet.md` §5 (R1–R7); здесь — влияющие на план:
R1 шрифты/кириллица (митигирован кандидатами OFL), R3 точность пагинации
(допуск ±1 стр., эталон-регресс), R5 доступность GitHub (зеркало),
R6 сложность imageMask (вынесен в v0.3.0+ с правом сдвига).

## 5. Правила пересмотра плана

- статус волны (дата завершения, фактический состав) — вносится в таблицу
  по факту, новой строкой истории ревизий;
- состав утверждённой волны меняется только решением владельца или находкой
  ревью — с фиксацией (код ВЛ/Ф) в строке волны;
- новые идеи — только через fp-карты (регламент §5), не прямым редактированием
  плана.

## 7. Документационный оборот волны (памятка)

Порядок действий каждой волны (регламент §1.6, §7):
1. до старта — строка волны в §1 (состав, DoD, РД) утверждена;
2. работа; точечные коммиты — «(АН-xx п.N)»;
3. подготовка пакета: update-vXXXX.md, правки [В]-документов, версии в шапках;
4. загрузка пакета, коммит «0.X.Y-draft»;
5. проверка (update §5, check-repo);
6. уведомление владельца → записки приёмки → priemka-v0XX.md → задачи
   следующей волны.
