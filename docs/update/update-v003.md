# Инструкция обновления v0.0.3-draft (волна приоритетов владельца)

**Дата:** 07.10.2026 · **Волна:** v0.0.3-draft · **Тип:** документационная
(кода сайта нет — запрет на код в подготовительных волнах сохраняется).
Формат разделов — регламент §7.2.

---

## 1. Что изменилось

**Задача волны:** обработка приоритетного списка владельца «Deigracht.
feature-proposals.md» от 07.10.2026 (закрытие ВЛ-02) — поручение «брать
в работу, пока владелец обновляет GitHub». Из списка взяты только порядок
выполнения (приоритеты) и комментарии владельца — шапка и подвал fp-документа
ведутся аналитиком (примечание владельца в файле).

Ключевые изменения:
1. **Порядок разработки утверждён владельцем (ВЛ-02 закрыт):** ядро №1–№5 —
   приоритет №0 (v0.1.0–v0.3.0) → важный функционал №10 (приоритет №1) →
   №11 (№2) → №17 (№3) → №13a (№4), волны v0.3.0–v0.6.0 → дополнительный
   №8 (№5) → №9 (№6) → №6 (№7) → №16 (№8), волны v0.7.0–v0.10.0 →
   **v1.0.0 «боевая рабочая версия сайта, интеграции»**: №18 (боевой №1) →
   №13b (боевой №2) → №15 (боевой №3) → №12 (боевой №4). План перестроен
   (plan-razrabotki ред. 1.2): 11 волн v0.1.0 → v1.0.0, ≈44–68 РД;
   независимые ревью — раунд 1 в v0.4.0, раунд 2 в v0.8.0, финальное перед
   v1.0.0 (регламент §6.3); новый риск R9 (длинная очередь волн).
2. **Изображения отложены до v1.0.0** (комментарий владельца к fp №2/№18):
   «все публикации изображения откладываются до реализации этого fp, до
   этого работаем исключительно с текстом и таблицами». Следствия:
   `![alt](url)` и `{{imageMask*}}` в черновых волнах — плейсхолдеры;
   матрица V3 (otchet §1.4) и эталон-метрики (9 картинок — плейсхолдеры)
   обновлены; АН-04 (CSP img-src) и АН-06 (imageMask) перенесены к v1.0.0;
   в черновике CSP `img-src 'self'` — строгий (SECURITY §2).
3. **Карта №13 разделена** (комментарий владельца «делим на a — без сервера,
   b — с сервером»): **№13a** — клиентская история (приоритет №4, v0.6.0);
   **№13b** — серверная (боевой приоритет №2, v1.0.0) — **гейт нового
   вопроса ВЛ-12**: серверная составляющая v1.0.0 («интеграции») уточняет
   рамки ВЛ-04; default — v1.0.0 без сервера (ВЛ-12 в voprosy ред. 2.1).
4. **fp №18 переназначен владельцем:** i18n → «Изображения внутри текстового
   блока» (боевой приоритет №1); полное описание по заметкам владельца
   подготовлено (поручение из списка — АН-13, закрыта); i18n перенесён на
   **fp №19** (≥v1.x, ВЛ-09). Прецедент переназначения номера задокументирован
   в правилах fp-документа (номер не был реализован/отменён).
5. **Комментарий владельца к fp №4:** модальное окно печати — с запретом
   скролла основной части сайта, пока открыто (требование приёмки v0.1.0).
6. **fp №7б** в списке владельца не упомянут — сохранён аналитиком в v0.3.0
   (основной способ передачи документов при ВЛ-04); владелец вправе
   переместить. **fp №6** (библиотека) — приоритет №7 (v0.9.0); минимальный
   контур сохранности (автосохранение + экспорт/импорт .md) перенесён
   в storage-минимум v0.1.0 (решение аналитика — пользователь не должен
   потерять документ до волны библиотеки).
7. Регламент ред. 1.2: **грабля №10** — инородные символы-включения
   (иероглифы-артефакты инструментов подготовки текста) дважды пойманы
   самопроверкой в волнах v0.0.1/v0.0.3; мера — скан символных диапазонов
   в финальной проверке волны и в check-repo с v0.1.0.
