# Инструкция обновления v0.1.2-draft (Pages: отключение Jekyll)

**Дата:** 07.10.2026 · **Волна:** v0.1.2-draft · **Тип:** точечная
(деплой-конфигурация + документы; кода сайта не меняет, кроме точки версии).
Формат разделов — регламент §7.2.

---

## 1. Что изменилось

**Задача волны:** устранить причину красных сборок GitHub Pages
(билды #17–#23 волны v0.1.1, лог в Actions):

```
github-pages 232 | Error: Liquid syntax error (line 95):
Variable '{{' was not properly terminated with regexp: /\}\}/
```

1. **Корень причины найден:** GitHub Pages по умолчанию собирает сайт
   **Jekyll'ом**; Jekyll рендерит все `.md`/`.html` репозитория через
   шаблонизатор **Liquid**, для которого `{{ … }}` — переменные шаблона.
   Синтаксис блоков Homebrewery V3, на котором построен весь проект
   (`{{note}}`, `{{wide}}`, `{{pageNumber,auto}}` — и упоминания в SECURITY/
   README/документации, и сам эталон), состоит из таких скобок → Jekyll
   падает на первом незакрытом `{{` (line 95 SECURITY.md) и сборка красная,
   сайт не публикуется (404 при включённом Pages — симптом этой же ошибки).
2. **Решение (грабля №14, регламент ред. 1.6):** проект — чистая статика
   (ADR-001), Jekyll не нужен. Пустой файл **`.nojekyll` в корне репозитория**
   отключает Jekyll: Pages раздаёт файлы как есть. Файл создан; внесён в
   REQUIRED check-repo (v1.2); процедура — `setup-repo-pages.md` шаг 2б;
   диагностика красных билдов теперь начинается с проверки `.nojekyll`
   (шаг 3б п.0).
3. **Чистка:** удаление `data/.keep` — артефакта экспериментов с папками
   (в структуре проекта его нет; реестр §7.3).
4. **Документы:** setup ред. 1.3 (шаг 2б, шаг 3б п.0), регламент ред. 1.6
   (грабля №14), реестр ред. 4.2, план ред. 1.5 (волна 1в; АН-17 закрыта —
   пакет v0.1.1 загружен, причина билдов найдена; АН-18 закрыта; АН-19 —
   загрузка этой волны), техпаспорт 0.1.2-draft (§4 — .nojekyll в структуре,
   §3 — хостинг с .nojekyll), версии точек синхронизации — 0.1.2-draft.
5. **«Бессмысленные» коммиты владельца (папки, .keep) оказались полезны:**
   каждый push триггерил сборку и вывел настоящую ошибку в лог — без них
   диагностика 404 осталась бы гаданием. Зафиксировано как практика: при
   «сайт не собирается» смотреть лог последнего билда в Actions первым делом.

  по умолчанию (GitHub Pages = Jekyll/Liquid) несовместим с синтаксисом

  ошибку — «бессмысленные» коммиты владельца её и проявили).
