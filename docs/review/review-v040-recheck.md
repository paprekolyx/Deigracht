## 3. Новые находки (Н-xx)

**Н-01 (критическая). `{{column-count:N … }}` молча теряет текст тела блока.**
blocks.js:88–96 (case `'column-count'`) возвращает только элемент-директиву
`data-cols`, `node.body` игнорируется; pages.js:169–173 саму директиву в
страницу не добавляет. Итог: содержимое, записанное внутри блока, **исчезает
из разворота без следа** — без плашки и предупреждения. Поражает три
собственных артефакта проекта:
- сниппет «Одна колонка {{column-count:1}}» (snippets.js:49–52) — его же текст
  «Текст в одну колонку (широкие таблицы, схемы)…» не рендерится;
- демо справки (help.js:76–79) — абзац «Этот абзац живёт на одноколоночной
  странице» не живёт нигде;
- **эталон приёмки**: все 17 блоков `{{column-count:2 …}}` — с телом
  (etalon-sint.md, строки 86, 149, 281, 1148, 1539, 1577, 1684, 1697, 2146,
  2163, 2193, 2304, 2694, 2950, 3141, 3465, 3747) — 17 абзацев текста молча
  теряются. DoD волны 2 «эталон рендерится корректно» и метрика страниц
  (pr030-З2/АН-20: предварительные 84/85) измерены на рендере с потерями.

В оригинальном Homebrewery тело такого блока отображается (публичные примеры
синтаксиса `{{column-count:2| …содержимое… }}`; PDF владельца содержит весь
текст). Нарушен собственный принцип проекта: «неизвестный модификатор —
видимая плашка, а не молчаливая поломка» (otchet §1.4) — здесь **известный**
модификатор молча «съедает» текст.
**Воспроизведение:** исходник `{{column-count:1\nТЕКСТ\n}}` → в развороте
«ТЕКСТ» отсутствует (проверено харнессом, run-checks.js проверки 1, 1б, 7).
**Место:** assets/js/blocks.js:88–96, assets/js/pages.js:169–173.
**Предложение ревьюера:** рендерить тело блока-директивы на новой странице с
N колонками (минимально: blocks.js возвращает директиву со списком дочерних
items; pages.js при открытии N-колоночной страницы выкладывает их первыми).
Промежуточная мера до фикса: честная плашка «содержимое директивы
column-count не отображается» + правка сниппета и демо справки на форму без
тела. В parser-smoke добавить проверку сохранения текста: каждый абзац AST
эталона присутствует в тексте отрендеренного DOM (сейчас smoke сверяет только
AST-счётчики — поэтому дефект не пойман).

**Н-02 (средняя). Пустая страница при директиве `{{column-count:N}}`.**
pages.js:171: `if (hasContent(current.body) || current.cols !== cols)
closePage(cols)` — если текущая страница **пуста**, но её число колонок ≠ N,
страница всё равно закрывается и остаётся в развороте пустой. Два типовых
сценария: (а) `\page` сразу перед директивой → пустая страница между ними;
(б) директива первым блоком документа → пустая страница №1. В печати/PDF это
пустая страница — тот же класс дефекта, что закрытая записка З1 (pr030-З1,
v0.3.1), и противоречие DoD «печать без пустых страниц».
**Воспроизведение:** `Первая страница текст.\n\n\page\n{{column-count:1}}\n
Текст главы.` → страницы: 1 (текст), 2 (**пустая**, cols=2), 3 (Текст главы,
cols=1); `{{column-count:3}}\nТекст.` первым блоком → страница 1 пустая
(проверено харнессом, проверки 3–4). Эталон сейчас не поражён (пар
`\page → column-count` нет), но сценарий «новая одноколоночная страница после
разрыва» для пользователя типичен.
**Место:** assets/js/pages.js:169–173.
**Предложение ревьюера:** если текущая страница пуста — применять N колонок к
ней (class `page--cols-N` + `data-cols`), а не открывать новую;
`closePage(cols)` только при непустой странице.

**Н-03 (средняя). Литеральный `####` в строках ручного оглавления.**
Паттерн эталона и документа владельца — `- #### [{{ Раздел 1 }}{{ 2 }}](#p2)`
(etalon-sint.md:15–21; в Homebrewery `####` внутри элемента списка даёт
заголовочное оформление строки). Парсер Deigracht оставляет `#### ` текстом
элемента списка, а `decorateToc` (blocks.js:31–50) переписывает только `<a>` →
отрендеренная строка оглавления выглядит как **«#### Раздел 1 …. 2»**.
Дефект виден на титульном развороте эталона и реального документа владельца;
frozen-метрики его не ловят (AST-счётчики не меняются), раунд 1 его не noted.
**Воспроизведение:** отрендерить TOC-фрагмент эталона →
`li[0].textContent === "#### Раздел 12"` (проверено харнессом, t6.js).
**Место:** assets/js/blocks.js:31–50 (decorateToc), assets/js/parser.js
(parseInline — inline-ATX отсутствует by design).
**Предложение ревьюера:** в decorateToc снимать префикс `/^#{1,6}\s+/` с
текста элемента перед разбором `{{…}}{{N}}` и опционально добавлять класс
уровня (`toc-h4`) для оформления; вектор в parser-smoke (раздел decorateToc-
логики можно вынести чистой функцией, как сделано для toc.js).

**Н-04 (средняя). Справка v0.4.0 (help.html) не демонстрирует автооглавление
и содержит повреждённый/неточный текст.**
(а) Демо `{{toc,auto}}` рендерится **пустой плашкой** «Оглавление: заголовков
уровня 3 не нашлось — уточните диапазон»: в демо-документе нет ни одного h3
верхнего уровня (только h1/h2; h3/h4 — внутри `{{monster}}`, они в состав не
входят by design). Пункт чек-листа приёмки upd040 §3 «справка: демо авто-TOC
показывает номера» в таком виде непроходим — feature-демо не показывает
feature (проверено харнессом, проверка 5: autoNav = 1, tocRows = 0,
toc-empty = 1).
(б) Правка Ф-04 внесена с повреждением текста: help.js:102–105 — абзац
обрывается на полуслове («Ниже — **автооглавление**: заголовки 3-го») и
дублируется началом следующего абзаца («**{{toc,auto}}** — автооглавление:
заголовки 3-го уровня…») — след неудачного слияния строк демо-массива.
(в) help.js:121: «**Ctrl+S** — сохранить .md в браузер **и скачать файл**» —
неправда: Ctrl+S только сохраняет в браузер (editor.js:170–177 → saveNow →
localStorage); скачивает файл кнопка «Сохранить .md».
(г) Якоря `#pN` оглавлений в справке — мёртвые: элементов `id="pN"` нет,
клик-обработчик живёт только в editor.js:280–288 (в help.html не подключён).
Для демо-страницы мелочь, но «живой справочник» с нерабочими ссылками теряет
доверие.
**Место:** assets/js/help.js:76–121, 147 (demoSrc), help.html.
**Предложение ревьюера:** добавить в демо пару h3 верхнего уровня (например,
подразделы «Врезки и флавор» / «Статблоки» внутри раздела блоков) — демо
авто-TOC начнёт показывать номера; починить оборванный абзац; исправить
описание Ctrl+S; при желании — подключить в help.js тот же обработчик `#pN`
(3 строки, копия editor.js).

**Н-05 (низкая). Ложная «несходимость» авто-TOC при двух разных диапазонах.**
`state.rendered` в toc.js — один слот (toc.js:155): при нескольких
`{{toc,auto}}` в документе он хранит записи **последнего** построенного
оглавления, а `collect()` (toc.js:171–183) сравнивает их с записями **первой**
спецификации (`findSpec`, toc.js:64–70). Если диапазоны различаются
(`{{toc,auto:1}}` + `{{toc,auto:3}}`), сравнение не сходится никогда → всегда
3 полных прохода пагинации и **ложное предупреждение** «автооглавление не
сошлось за 3 прохода» в статус-баре, даже когда все номера правильные.
Комментарий toc.js:64–65 («оглавлений-авто может быть несколько») такое
использование легализует.
**Воспроизведение:** документ с `{{toc,auto:1}}` и `{{toc,auto:3}}` →
pass = 3, stable = false, номера в обоих оглавлениях корректны (проверено
харнессом, проверка 8; с одинаковыми диапазонами — сходится за 2, проверка 9).
**Место:** assets/js/toc.js:155, 171–183, assets/js/editor.js:29–34.
**Предложение ревьюера:** хранить `rendered` как карту spec-ключ → записи и
сравнивать по всем авто-оглавлениям; либо (дешевле) зафиксировать честную
границу «один авто-диапазон на документ» в tehpasport §10 и справке.

**Н-06 (низкая). Некорректная спецификация `auto:` молча отключает автосборку.**
Regex parseSpec (`/^auto(?::\s*(\d)(?:\s*-\s*(\d))?)?$/`, toc.js:43) принимает
только **однозначные** цифры: `{{toc,auto:10}}`, `{{toc,auto:2-}}`,
`{{toc,auto:x}}` не матчатся → `auto: false` → блок уходит в ветку ручного
TOC (blocks.js:84–87) и рендерится **пустым nav без плашки и предупреждения**
(тело-то пустое). Ф-03 (clamp 1–6) закрыл только однозначные 0–9.
**Воспроизведение:** `DG.toc.parseSpec('toc,auto:10')` → `{auto:false,…}`;
рендер `{{toc,auto:10}}` → пустой `nav.block-toc`, `.toc-empty` отсутствует
(проверено харнессом, проверки 10–11).
**Место:** assets/js/toc.js:39–60.
**Предложение ревьюера:** ловить токен `auto` независимо от корректности
диапазона: `/^auto\b(?::\s*(\d+)\s*(?:-\s*(\d+)\s*)?)?/` + clamp 1–6;
неразбранный остаток — плашка «некорректный диапазон уровней» (культура
честных плашек).

**Н-07 (низкая). `window.SITE_VERSION` всегда undefined: пустой чип версии в
справке и безверсионный комментарий экспорта.**
config.js:8 объявляет `const SITE_VERSION` — const верхнего уровня
классического скрипта не становится свойством `window`. help.js:147 и
export.js:74 читают именно `window.SITE_VERSION || ''` → чип `#help-version`
в help.html пустой, а комментарий в экспортированном .html всегда без версии
(«Экспорт Deigracht  · самодостаточный файл:»). editor.js:201 использует
«голый» идентификатор — работает.
**Воспроизведение:** открыть help.html — чип версии пуст; Node:
`typeof window.SITE_VERSION === 'undefined'` при живом `SITE_VERSION`
(проверено харнессом, проверка 14).
**Место:** assets/js/help.js:147, assets/js/export.js:74, assets/js/config.js:8.
**Предложение ревьюера:** читать `SITE_VERSION` напрямую (как editor.js) либо
один раз положить `DG.config.siteVersion = SITE_VERSION` в config.js и
использовать везде её (заодно исчезнет расхождение стилей).

**Н-09 (низкая). safeUrl: protocol-relative URL проходит как «относительный»;
mailto-рассогласование парсера и whitelist.**
util.js:26: `s.startsWith('/')` пропускает `//evil.com/x` — ссылка в документе
может вести на внешний хост, выглядя относительной. XSS здесь нет (схемы
`javascript:`/`data:` по-прежнему отклоняются, вектора smoke зелёные), но это
расходится с заявленным whitelist «http/https + относительные + якоря»
(SECURITY §2). Вторая половина: parser.js:30 (RE.autolink) специально
распознаёт `<mailto:…>`, но safeUrl `mailto:` отклоняет → autolink-mailto
рендерится как «ссылка отклонена» — код сам с собой не согласован.
**Воспроизведение:** `DG.util.safeUrl('//evil.com/x')` → `'//evil.com/x'`;
`safeUrl('mailto:a@b.c')` → `null` (проверено).
**Место:** assets/js/util.js:22–30, assets/js/parser.js:30.
**Предложение ревьюера:** отклонять (или явно резолвить в `https:`) строки,
начинающиеся с `//`; по mailto — решение владельца: либо убрать `mailto` из
autolink, либо добавить схему в whitelist и в SECURITY §2 (оба варианта в
рамках ограничений).

**Н-10 (низкая, на границе с наблюдением). `_курсив_` внутри слова.**

от оригинала.

**Предложение ревьюера:** либо проверка word-boundary для `_` (как в GFM),
либо честная строка расхождений в otc §1.4 — на выбор аналитика.

## 5. Подтверждённые области (проверено — чисто)

- **XSS-модель:** `innerHTML`/`eval`/`document.write`/`insertAdjacentHTML`
  отсутствуют во всём коде; пользовательский текст — только
  textContent/createTextNode; ссылки — safeUrl + `rel="noopener noreferrer"`
  для внешних; отклонённые схемы — видимый `.badlink`. 10 safeUrl-векторов и

  (outerHTML) — инъекция исключена, `<title>` экранируется `esc()`.
- **CSP:** index.html и help.html — строка в строку как заявлено в SECURITY
  §2; 404.html — строже (`script-src 'none'`); стиль-инъекция `@page`
  (pdf.js) соответствует заявленному исключению `style-src 'unsafe-inline'`.
- **Локальность/зависимости:** ноль внешних ресурсов (check-repo §7 + ручной
  grep); 20 woff2 + 4 OFL на месте, fonts.css ссылается только на
  существующие файлы; unicode-range-подмножества cyrillic+latin корректны.
- **Данные:** не покидают браузер; localStorage-квота — честное
  предупреждение (storage.js saveDoc → editor.js «экспортируйте .md»);
  секретов в дереве нет (check-repo §10 + просмотр).

## 6. Наблюдения (не находки — без действий или на усмотрение)

1. Инлайн-форма Homebrewery `{{column-count:2| …содержимое… }}` (в одну
   строку, через `|`) не поддержана — содержимое уйдёт в modsRaw и тоже
   потеряется. В эталоне/документе владельца не встречается; станет релевантна
   при открытии чужих документов — кандидат в бэклог-строку otc §1.4 «прочее
   V3 — по мере встречаемости».

   он не вендорится (tokens.css `--ui-mono` — системный стек). Tehpasport §13
   честен (4 семейства); расхождение формальное, достаточно одной строки
   примечания в ADR при следующей ревизии otc.
3. В экспортированном .html нет CSP-мета — приемлемо: скриптов в экспорте
   нет, стили инлайновые; чек-лист SECURITY §6 («экспорт не содержит ничего
   лишнего») при v1.0.0 это покроет.
4. `data/.keep`, ведущий CRLF у части HTML/CSS — известные безвредные
   отклонения (грабля №13, решение владельца), не находки.
5. Reglament §10: строки регистра грабель идут в порядке 1–10, 12, 13, 14,
   **11** — косметика, на усмотрение.
