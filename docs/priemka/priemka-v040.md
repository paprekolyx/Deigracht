### З1 (pr040-З1). README.md в редакторе: строки кодового блока налезают на вторую колонку (07.10.2026)

- **Вопрос (слова владельца, 07.10.2026):** при просмотре README.md через
  проектный сайт часть текстов уезжает во второй столбец: строки кодового
  блока «Структура репозитория» длиннее колонки и рисуются поверх текста
  второй колонки (скриншот — сообщение владельца 07.10.2026, в рабочей
  области чата `uploads/9_image.png`).
- **Причина (аналитик):** `.page-body pre` (theme-book.css) не объявляет
  `white-space: pre-wrap`: в многоколоночном развороте (`.page-body {
  column-count: 2 }`) длинные неделимые строки кода не переносятся и
  вылезают за пределы своей колонки, перекрывая соседнюю; в печати/PDF
  картина та же. Дефект классовый, не частный: любой документ с длинными
  строками кода (README, технические главы) воспроизводит его.
- **План (аналитик):** волна v0.4.1 — `.page-body pre { white-space:
  pre-wrap; overflow-wrap: break-word; }` (экран и печать); чек-лист
  приёмки v0.4.1: открыть README.md в редакторе — перекрытий нет, код
  переносится по словам; регресс: эталон и демо справки без изменений.
  Кандидат в грабли №15 (реестр регламента §10 — в пакете v0.4.1).
- **Статус:** 🔶 в план v0.4.1 (черновик `Work/update-v041.md`, позиция
  «З1-pr040»; публикация плана — после старта волны).

### З3 (pr040-З3). Wide-таблицы во всю ширину разворота (вики-заметка 5, 07.10.2026)

- **Записка владельца:** «Wide таблицы, которые занимают всю ширину
  страницы, а не только одну из колонок — fp с высоким приоритетом
  (проверить наличие похожих fp — добавить в тот пункт / создать новую
  карточку fp и расположить на приоритете следующей волны)».
- **Проверка аналитика (по указанию «проверить похожие fp»):** механизм
  существует с v0.2.0 (fp №2 ч.2, реализован): блок `{{wide}}` —
  `.block-wide { column-span: all }` (theme-book.css:318–320), сниппет
  «Широкий блок {{wide}}»; таблица внутри `{{wide}}` занимает обе колонки
  разворота. Похожая карта — fp №2 ч.2 — реализована (статусная заглушка,
  дополнить её нельзя по правилам ведения) → создана **новая карта fp №20**
  (проверка на документе владельца + эргономика: сниппет «Широкая таблица»,
  поведение дробления внутри wide, опционально авто-wide — состав в карте).
- **Маршрут:** fp №20 (fp ред. 2.5), приоритет высокий (указание владельца);
  целевая волна — кандидат v0.5.0 (v0.4.1 — корректировочная волна, новых
  fp-возможностей не несёт: журнал review-v040-recheck, запись 2; окончательный
  состав v0.5.0 утверждает владелец). Смежно: ВЛ-15 (дробление длинных таблиц
  в колонках) — ответ владельца 07.10.2026: гибрид, реализация в v0.4.1.
- **Статус:** 🔶 fp №20 (очередь — решение владельца при планировании).
