# Технический паспорт Deigracht

**Версия проекта:** 0.1.0-draft · **Дата паспорта:** 07.10.2026
**Статус:** фактическое состояние волны v0.1.0 — редактор реализован
(статический сайт, первая кодовая волна); паспорт ведётся с волны 0
и синхронизирован с кодом.
**Связанные документы:** `docs/reglament.md` (правила) · `docs/reestr.md`
(реестр) · `docs/plan/otchet.md` (анализ и ADR) ·
`docs/plan/plan-razrabotki.md` (волны) · `docs/feature-proposals.md` (бэклог)

## 1. Общие сведения

**Deigracht** (название утверждено владельцем 07.10.2026, ВЛ-01; проверка
уникальности — `docs/plan/otchet.md` §7) — статический веб-редактор для оформления
хоумбрю-документов к D&D и другим НРИ: Markdown-исходник → книжный разворот
в стиле официальной книги правил → PDF печатью браузера. Образец —
The Homebrewery (MIT), недоступный автору; отличия — первоклассная
кириллица, ноль внешних CDN, ноль серверов.

**Рамки проекта (ВЛ-04, 07.10.2026):** сугубо индивидуальный инструмент —
без аккаунтов, публикации документов и шаринга по ссылке; передача
документов — файлами (PDF, .md, самодостаточный .html). v1.0.0 — «боевая
рабочая версия» (приоритеты владельца, ВЛ-02 от 07.10.2026); серверная
составляющая возможна только в рамках вопроса ВЛ-12 (хранилище картинок/
история версий — без аккаунтов и шаринга), default — полностью клиентский
релиз. **Черновые волны v0.1.0–v0.10.0 работают только с текстом и
таблицами** — изображения отложены до v1.0.0 (fp №18, решение владельца
07.10.2026).

**Стадия:** подготовка (0.0.x). Черновик сайта (0.x) — статический макет
на GitHub Pages без базы и аккаунтов.

## 2. Архитектура (план)

```
        Пользователь (браузер)
              │
              ▼
┌─────────────────────────────────────────────────────┐
│  Статический сайт (GitHub Pages; HTML/CSS/JS без     │
│  сборки, ноль внешних CDN)                          │
│                                                      │
│  index.html — редактор                               │
│  ┌──────────────┐   исходник   ┌──────────────────┐  │
│  │ Панель Markdown│ ─────────▶ │ Конвейер рендера │  │
│  │ (textarea/     │  (на лету) │ parser.js → MD-  │  │
│  │  contenteditable)           │ AST → blocks.js  │  │
│  └──────────────┘              │ (V3-блоки) →     │  │
│         ▲                      │ render.js (DOM)  │  │
│         │                      │ → pages.js       │  │
│  storage.js                    │ (пагинация)      │  │
│  (localStorage/                └────────┬─────────┘  │
│   IndexedDB)                            ▼            │
│  библиотека документов        Разворот книги         │
│  в браузере пользователя      (theme-book.css)       │
│                                       │              │
│                               print.css + window.    │
│                               print() → PDF          │
│                               (переключатель         │
│                                A4/Letter — ВЛ-07)    │
└─────────────────────────────────────────────────────┘
        Сервера, базы, аккаунтов — НЕТ (решение ВЛ-04)
```

Ключевые решения (подробно — `docs/plan/otchet.md` §2, §4):
- **ADR-001 «Статика без сборки»**: vanilla JS ES6+, модули `<script defer>`,
  никаких фреймворков/бандлеров/CDN; сайт открывается двойным кликом
  по index.html (file://) и с Pages одинаково.
- **Собственный парсер** Markdown+V3: HTML строится программно (XSS-безопасно,
  SECURITY §2), синтаксис — совместимость с Homebrewery V3 (эталон приёмки —
  документ владельца).
- **Пагинация**: фиксированные «страницы»-контейнеры (.page, CSS columns)
  + JS-измерение переполнения; `\page` — принудительный разрыв; экспорт —
  `@page`-геометрия, 1 экранная страница = 1 печатная; формат — A4/Letter
  (переключатель, дефолт Letter — ADR-003 ред. 1.1).

## 3. Стек и обоснование

| Слой | Решение | Обоснование |
|---|---|---|
| Вёрстка | HTML5 + CSS3, дизайн-токены на CSS-переменных | установленная практика; тема книги = набор токенов (цвета, шрифты, поля) — задел для fp №8 «свои темы» |
| JS | vanilla ES6+, без сборки | ADR-001; поддержка без toolchain |
| Парсер | собственный (parser.js + blocks.js) | ноль зависимостей; контроль XSS; точная подгонка под V3-синтаксис |
| Шрифты | OFL с кириллицей, woff2 локально, готический склад | боль оригинала: латинские книжные шрифты без кириллицы → Times New Roman fallback (otchet §1.3); кандидаты — ADR-002 ред. 1.1 (ВЛ-08) |
| Текстуры | CC0/собственные (пергамент, орнаменты) | не используем ассеты WotC и Homebrewery (LICENSE ч.3, ВЛ-11) |
| PDF | print-CSS + window.print(), A4/Letter | без серверов; как в Homebrewery (браузерная печать) |
| Хранилище | localStorage/IndexedDB | сервера нет (ВЛ-04); честные границы — SECURITY §3 |
| Хостинг | GitHub Pages | решение владельца 07.10.2026; зеркало при блокировках — otchet §5, R5 |
| Тесты | tests/check-repo.py (с v0.1.0) | установленная практика; exit 0 = индикатор волны |

## 4. Состав репозитория

**Факт (v0.1.0)** — структура реализована:

```
index.html               редактор (единственная страница черновика)
404.html                 страница «не найдено» (для Pages)
assets/css/              tokens.css · editor.css · theme-book.css · print.css
assets/js/               config.js (SITE_VERSION) · util.js (esc/safeUrl) ·
                         parser.js · blocks.js · render.js · pages.js ·
                         editor.js · storage.js · pdf.js · help.js
assets/fonts/            *.woff2 (OFL, кириллица; перечень и лицензии — §13)
assets/img/              пергамент, орнаменты, favicon (иконка книги — ВЛ-03)
docs/                    документация (состав — docs/reestr.md)
data/etalon/             эталонный документ + метрики рендера (регресс)
tests/check-repo.py      автопроверка целостности
```

Отличия факта от плана: добавлены `assets/css/fonts.css` (сгенерирован из
`assets/fonts/manifest.json`), `tests/parser-smoke.js` (регресс эталона),
`data/etalon/` (эталон + frozen-метрики). Поздние страницы (бэклог):
`help.html` (справка синтаксиса + юридическая памятка — fp №10, ЮР-03).
Страница просмотра по ссылке — не планируется (ВЛ-04); её заменяет экспорт
самодостаточного .html (fp №7б).

## 6. Данные и формат документа

- Формат документа — текстовый (Markdown + metadata-блок), **совместимый
  с Homebrewery V3**: тот же `.md` открывается и там, и у нас (в пределах
  поддержанного синтаксиса). Metadata: ```` ```metadata ````-блок в начале
  (title, description, tags, systems, renderer, theme) — парсится и не
  рендерится.
- Хранение в черновике: ключ → документ (localStorage, лимит ~5 МБ;
  IndexedDB для библиотеки — fp №6, v0.3.0). Экспорт/импорт файла —
  основной способ переноса и бэкапа (SECURITY §3.2).
- Серверной базы нет и не планируется (ВЛ-04): раздел миграций/схем БД
  в паспорте не появится, пока рамки проекта не пересмотрены.

## 7. Безопасность

Полностью — `SECURITY.md`. Кратко: XSS-защита программным построением DOM;
whitelist схем ссылок (safeUrl — очистка от управляющих символов до проверки
схемы); CSP `default-src 'self'`; ноль CDN/зависимостей; ПДн не собираются
(ЮР-02); секреты вне git.

## 9. Производительность и эксплуатационные заметки

Заполняется фактическими уроками волн (правило: новый эксплуатационный
урок = новый пункт). Целевые ориентиры v0.1.0: рендер эталонного документа
(180 тыс. знаков) — debounce ≤300 мс на правку, полный перерендер ≤2 с
на среднем ноутбуке; Lighthouse (Pages) ≥90 доступность.

1. **(v0.1.0)** Парсер: эталон 180 513 знака → AST (1 379 блоков) за ~50 мс
   (Node 20; полный прогон parser-smoke с 51 проверкой — ~145 мс). Узкое
   место — не парсинг, а пагинация измерением (forced reflow на каждый
   батч): батч 8 блоков + откат (config.paginateBatch) — браузерные замеры
   заносятся в приёмку update-v010 §4; при деградации на больших документах —
   ленивая пагинация видимых страниц (кандидат в v0.2.0).
2. **(v0.1.0)** Шрифты: 20 файлов woff2 (~470 КБ, 4 семейства × 2 подмножества)
   грузятся с font-display: swap — первая отрисовка возможна системным
   шрифтом, замена без блокировки.
3. **(v0.1.0)** Полный перерендер на каждое изменение (v0.1.0) — приемлемо
   при debounce 300 мс; инкрементальный рендер — кандидат v0.2.0+ при
   замерах >2 с на эталоне.

## 10. Известные ограничения черновика

1. Документы живут только в браузере одного устройства — по замыслу (ВЛ-04):
   перенос и передача — экспорт `.md` / самодостаточного `.html` / PDF;
2. шаринга по ссылке и аккаунтов нет и не планируется (ВЛ-04) — осознанная
   граница проекта, не дефект;
3. изображения в документах не рендерятся в черновых волнах v0.1.0–v0.10.0 —
   решение владельца 07.10.2026 (плейсхолдеры); с v1.0.0 — внешние hotlink-URL
   (fp №18; приватность/битые ссылки — SECURITY §3.3; встраивание base64
   на клиенте — fp №12);
4. точная пагинация в браузере принципиально сложнее серверной вёрстки —
   возможны расхождения ±страница с оригиналом Homebrewery при сложном
   материале (риск R3 — otchet §5);
5. поддержка синтаксиса V3 — частичная по волнам (матрица — otchet §1.4);
   `{{imageMask*}}` — самая сложная часть, может сдвинуться за v0.3.0;
6. GitHub Pages может быть недоступен из РФ (зеркало — otchet §5, R5);
7. интерфейс только на русском (ВЛ-09); i18n — fp №19, не раньше v1.x;
8. пагинация v0.1.0: блок крупнее страницы не разрезается — помещается
   на отдельную страницу с видимой отметкой и предупреждением в статус-баре
   (дробление абзацев/таблиц по строкам — v0.2.0); синхронная прокрутка
   панелей — приблизительная (по пропорции);
9. парсер v0.1.0: списки — до 3 уровней вложенности; setext-заголовки
   (подчёркиванием) не поддерживаются; инлайн-`{{…}}` (например, в ссылках
   TOC) остаются текстом до v0.2.0;
10. документы — только localStorage одного браузера (квота ~5 МБ; при
    переполнении — предупреждение «экспортируйте .md»; IndexedDB — fp №6).

## 11. Серверная часть — НЕ планируется

Решение владельца (ВЛ-04, 07.10.2026): проект сугубо индивидуальный —
ни аккаунтов, ни публикации документов, ни шаринга по ссылке; достаточно
PDF/экспорта файлов. Упоминания «боевого блока» в документах ранних редакций
читать как «стабильный релиз v1.0.0 (статика)». Если рамки когда-либо будут
пересмотрены: новый ADR, ревизия SECURITY.md и LICENSE.md до реализации,
сервер — только на российском хостинге, авторизация — по отраслевому
минимуму (SECURITY §3.1).
