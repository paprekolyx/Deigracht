**Версия проекта:** 0.0.1-draft · **Дата паспорта:** 07.10.2026
**Статус:** каркас волны 0 — сайта и кода ещё нет; паспорт ведётся

## 1. Общие сведения

**Grimoire** (название — рабочая заглушка, ВЛ-01) — статический веб-редактор
для оформления хоумбрю-документов к D&D и другим НРИ: Markdown-исходник →
книжный разворот в стиле официальной книги правил → PDF печатью браузера.
Образец — The Homebrewery (MIT), недоступный автору; отличия — первоклассная
кириллица, ноль внешних CDN, ноль серверов в черновике.

**Стадия:** подготовка (0.0.x). Черновик сайта (0.x) — статический макет
на GitHub Pages без базы и аккаунтов. Боевая версия (если потребуется
серверный шаринг) — отдельный этап с пересмотром этого паспорта.

## 2. Архитектура (план)

```
        Пользователь (браузер)
              │
              ▼
┌─────────────────────────────────────────────────────┐
│  Статический сайт (GitHub Pages; HTML/CSS/JS без     │
│  сборки, ноль внешних CDN)                          │
│                                                      │
│  index.html — редактор                               │
│  ┌──────────────┐   исходник   ┌──────────────────┐  │
│  │ Панель Markdown│ ─────────▶ │ Конвейер рендера │  │
│  │ (textarea/     │  (на лету) │ parser.js → MD-  │  │
│  │  contenteditable)           │ AST → blocks.js  │  │
│  └──────────────┘              │ (V3-блоки) →     │  │
│         ▲                      │ render.js (DOM)  │  │
│         │                      │ → pages.js       │  │
│  storage.js                    │ (пагинация)      │  │
│  (localStorage/                └────────┬─────────┘  │
│   IndexedDB)                            ▼            │
│  библиотека документов        Разворот книги         │
│  в браузере пользователя      (theme-book.css)       │
│                                       │              │
│                               print.css + window.    │
│                               print() → PDF          │
└─────────────────────────────────────────────────────┘
        Сервера, базы, аккаунтов — НЕТ (черновик)
```

Ключевые решения (подробно — `docs/plan/otchet.md` §2, §4):
- **ADR-001 «Статика без сборки»**: vanilla JS ES6+, модули `<script defer>`,
  никаких фреймворков/бандлеров/CDN — наследие Sisku; сайт открывается
  двойным кликом по index.html (file://) и с Pages одинаково.
- **Собственный парсер** Markdown+V3: HTML строится программно (XSS-безопасно,
  SECURITY §2), синтаксис — совместимость с Homebrewery V3 (эталон приёмки —
  документ владельца).
- **Пагинация**: фиксированные «страницы»-контейнеры (.page, CSS columns)
  + JS-измерение переполнения; `\page` — принудительный разрыв; экспорт —
  `@page`-геометрия (A4/Letter), 1 экранная страница = 1 печатная.

## 3. Стек и обоснование

| Слой | Решение | Обоснование |
|---|---|---|
| Вёрстка | HTML5 + CSS3, дизайн-токены на CSS-переменных | паттерн Sisku; тема книги = набор токенов (цвета, шрифты, поля) — задел для fp №8 «свои темы» |
| JS | vanilla ES6+, без сборки | ADR-001; аудитория кода — владелец+аналитик, поддержка без toolchain |
| Парсер | собственный (parser.js + blocks.js) | ноль зависимостей; контроль XSS; точная подгонка под V3-синтаксис |
| Шрифты | OFL с кириллицей, woff2 локально | боль оригинала: Bookinsanity/Scaly Sans без кириллицы → Times New Roman fallback (otchet §1.3); кандидаты — otchet §4.4 |
| Текстуры | CC0/собственные (пергамент, орнаменты) | не используем ассеты WotC и Homebrewery (LICENSE ч.3) |
| PDF | print-CSS + window.print() | без серверов; как в Homebrewery (браузерная печать) |
| Хранилище | localStorage/IndexedDB | черновик без сервера; честные границы — SECURITY §3 |
| Хостинг | GitHub Pages | решение владельца 07.10.2026; зеркало при блокировках — otchet §5 |
| Тесты | tests/check-repo.py (с v0.1.0) | паттерн Sisku; exit 0 = индикатор волны |

**Сейчас (v0.0.1):** только документы — полный состав в `docs/reestr.md`.

**Целевая структура (с v0.1.0):**


## 6. Данные и формат документа

- Формат документа — текстовый (Markdown + metadata-блок), **совместимый
  с Homebrewery V3**: тот же `.md` открывается и там, и у нас (в пределах
  поддержанного синтаксиса). Metadata: ```` ```metadata ````-блок в начале
  (title, description, tags, systems, renderer, theme) — парсится и не
  рендерится.
- Хранение в черновике: ключ → документ (localStorage, лимит ~5 МБ;
  IndexedDB при превышении — решение в fp №6). Экспорт/импорт файла —
  основной способ переноса и бэкапа (SECURITY §3 п.2).
- Серверной базы нет; схема БД появится только в боевом блоке (шаринг) —
  тогда паспорт получит §6 в полном объёме (таблицы, политики, миграции
  нумерованными идемпотентными скриптами — паттерн Sisku supabase/).

## 7. Безопасность

Полностью — `SECURITY.md`. Кратко: XSS-защита программным построением DOM;
whitelist схем ссылок (safeUrl — паттерн Sisku v0.14.0); CSP `default-src
'self'`; ноль CDN/зависимостей; ПДн не собираются; секреты вне git.

## 9. Производительность и эксплуатационные заметки

Заполняется фактическими уроками волн (правило: новый эксплуатационный
урок = новый пункт). Целевые ориентиры v0.1.0: рендер эталонного документа
(180 тыс. знаков) — debounce ≤300 мс на правку, полный перерендер ≤2 с
на среднем ноутбуке; Lighthouse (Pages) ≥90 доступность. Сейчас: заметок нет
(кода нет).

## 10. Известные ограничения черновика

1. Документы живут только в браузере одного устройства (нет синхронизации);
2. нет шаринга по ссылке (боевой блок, fp №7);
3. картинки — внешние hotlink-URL (приватность/битые ссылки — SECURITY §3.3;
   загрузка в хранилище — fp №12);
4. точная пагинация в браузере принципиально сложнее серверной вёрстки —
   возможны расхождения ±страница с оригиналом Homebrewery при сложном
   материале (риск R3 — otchet §5);
5. поддержка синтаксиса V3 — частичная по волнам (матрица — otchet §1.4);
   `{{imageMask*}}` — самая сложная часть, может сдвинуться за v0.3.0;
6. GitHub Pages может быть недоступен из РФ (зеркало — otchet §5, R5).

## 11. Боевая версия (если понадобится сервер)

Триггер — решение владельца о шаринге/аккаунтах (ВЛ-04). Тогда: выбор
российского хостинга (паттерн Sisku otchet §2: Beget PHP+MySQL или Yandex
Cloud), настоящая авторизация по модели Sisku (bcrypt/argon2id, сессии,
CSRF, rate-limit, 2FA, audit_log), миграции нумерованными скриптами,
ревизия SECURITY, юридический минимум (политика ПДн, уведомление РКН —
ЮР-02). До этого решения черновик остаётся полностью клиентским.
