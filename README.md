# GRIMOIRE · редактор красивых документов для D&D

> **v0.0.1-draft · 07.10.2026.** Волна подготовки проекта: репозиторий,
> документы, правила, план. **Кода сайта ещё нет** — первая кодовая волна
> v0.1.0 (см. `docs/plan/plan-razrabotki.md`). Название Grimoire — рабочая
> заглушка (как Sisku на старте), будет заменено по решению владельца
> (вопрос ВЛ-01, `docs/plan/voprosy-vladeltsu.md`).

Веб-редактор для оформления хоумбрю-материалов к D&D и другим настольным
ролевым играм: слева пишешь Markdown — справа видишь книжный разворот
в стиле официальной книги правил: пергаментный фон, две колонки, фигурные
заголовки, статблоки монстров, врезки-заметки, широкие блоки на всю страницу,
оглавление с номерами страниц, разрывы страниц — и экспорт в PDF печатью
браузера. Идеологический образец — **The Homebrewery** (naturalcrit.com,
MIT License), недоступный автору проекта; цель — тот же инструмент, но
с **первоклассной кириллицей** (в оригинале книжные шрифты не содержат
кириллицы и русский текст проваливается в Times New Roman), без внешних CDN
и с полностью открытым кодом.

**Сайт-черновик:** ещё не опубликован — появится на `https://paprekolyx.github.io/Grimoire/` с волны v0.1.0
**По работе проекта писать:** Albert23NO@ya.ru — ведущий аналитик проекта

## Что будет у сайта (согласованный состав волн v0.1–v0.3 «ядро»)

| Возможность | Состав |
|---|---|
| Редактор с живым предпросмотром | две панели: Markdown-исходник → книжный разворот; прокрутка и правки без перезагрузки |
| Синтаксис Homebrewery V3 | ```` ```metadata ````-блок (title/description/tags/renderer/theme), `{{wide}}`, `{{note}}`, `{{descriptive}}`, `{{monster}}`, `{{toc}}`, `{{column-count}}`, `{{pageNumber}}`, `{{imageMask*}}`, `\page`, `___`-статблоки, таблицы, картинки по URL |
| Тема «книга правил» (5ePHB-стиль) | пергамент, колонки, цветные заголовки, буквицы, рамки врезок, статблоки с красными линейками; **шрифты — OFL с кириллицей, локально (woff2)** |
| Экспорт в PDF | print-раскладка (`@page`, геометрия A4/Letter), колонтитулы и номера страниц, печать браузером без серверов |
| Импорт существующих документов | вставил/загрузил `.md` из Homebrewery — получил тот же документ; **критерий приёмки ядра: документ владельца «Всемирная история» (65 стр., ~180 тыс. знаков, 211 `{{`-блоков, 49 `\page`, 3 монстр-блока, 577 строк таблиц) рендерится и печатается корректно** |
| Сохранение в браузере | черновик без сервера: документ живёт в localStorage/IndexedDB пользователя; библиотека документов — fp №6 |

Бэклог (шаринг по ссылке, свои темы, сниппеты, мобильная адаптация и др.) —
нумерованные fp-карты в **`docs/feature-proposals.md`**; порядок разработки
утверждается владельцем (ВЛ-02).

## Стек (план; обоснование и ADR — `docs/plan/otchet.md` §4)

| Слой | Технология |
|---|---|
| Вёрстка | HTML5, CSS3 (дизайн-токены на CSS-переменных), vanilla JS (ES6+) без сборки — подход проекта Sisku |
| Парсер | собственный Markdown-парсер + надстройка блоков V3 (без внешних зависимостей и CDN) |
| Шрифты | OFL-шрифты с кириллицей, локально woff2 (кандидаты — `docs/plan/otchet.md` §4.4; выбор — ADR волны v0.1.0) |
| PDF | print-CSS + `window.print()` — без серверной генерации |
| Данные | в черновике сервера и базы нет: документы в localStorage/IndexedDB браузера |
| Хостинг | GitHub Pages (Deploy from a branch); репозиторий публичный |

Принцип Sisku переносится дословно: **ноль внешних CDN** — всё вендорим
или пишем сами.

## Правила ведения проекта (кратко; полностью — `docs/reglament.md`)

- **Волна ≈ один MINOR** (SemVer): у волны есть состав работ, DoD и оценка
  в РД; версия `0.0.x` — подготовка (документальные волны), `0.x` — черновик.
- **Документы живут в репозитории** и синхронны версии: шапки README /
  LICENSE / SECURITY несут «Версия документа: 0.X.Y-draft · ДАТА».
- **Каждая волна = новый файл** `docs/update/update-vXXXX.md` (созданные
  не редактируются); приёмка — `docs/priemka/`, ревью — `docs/review/`.
- **Коммит** — либо версия пакета («0.0.1-draft»), либо ссылка на задачу
  («(АН-03 п.2, ВЛ-01)»).
- **Честные границы**: упрощения черновика перечислены явно (SECURITY.md,
  README), SECURITY описывает фактическое состояние, а не намерения.
